# 给小模型的维护工单模板

复制下面内容，填写方括号。不要把整本手册塞进提示词。

```text
你在维护 MC Clicker 2.0。任务：[玩家症状/明确要改的值或文字]。
目标版本：[网页/小红书/公共修复]；工作目录：[游戏根目录]。
另一版目录：[路径；没有就明确说明未同步]。
允许修改：[文件/职责范围]。期望行为：[前后例子]。
验收：[一个正常场景、一个失败/取消场景、需保留的行为]。
发布权限：[本轮只改本地 / 已授权推送部署]。

先读 AGENTS.md、docs/maintenance/README.md、TASK-ROUTER.md。
然后只读相关专章与真实调用处。先检查 git status，不覆盖别人的未提交内容。
用文件与函数说明：规则由谁决定、UI从哪里读、状态是否持久化、是否有平台差异。
如果反馈已被现有代码解决，给复现与验证证据，不重复改造。

按最小范围实施；不顺带格式化大文件、不把显示值当成结算值、
不改 IDs/已发布存档字典，不整文件覆盖 main.js/world.js 的平台差异。
公共修改逐段同步两版；check:editions 失败先读差异，不批量刷新哈希。
涉及规则先运行相关测试；UI跑真实页面；发版按 RELEASE-CONTRACT。
更新维护索引 node scripts/maintenance/scan.mjs；专章职责改变才修专章。
需要跨结算、存档格式、前台生命周期、场景缓存时，先提交发现与最小方案，
不要自行把这些变成顺手优化。

交付：修改文件、前后行为、执行过的命令与结果、未验证项、双版/发布状态。
没有证据不声称真机、性能或整局节奏已通过。
```

日常不必每次请多个代理。单一模型沿这条路径完成，复杂或失败项再升级审查。重大的数值调整仍需要明确目标和模拟；“只改一个数字”不代表游戏节奏只受一点影响。

维护扫描需要完整源码、脚本及固定测试输入。稀疏副本缺少相对依赖时，生成和 `--check` 都应失败；先补齐已跟踪输入，不能改为忽略。主站整仓清单由 `inventory.mjs` 单独生成，不随一次游戏小修更新。
