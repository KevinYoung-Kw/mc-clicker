# MC Clicker 2.0 维护入口

适用：网页版 V1.8.9（线上）/ 小红书 V1.8.9-xhs.1（已推送、未提审）。核查日期：2026-09-13。

**接一个小任务，不要通读整个仓库。** 先确认版本与修改范围，再按任务定位代码。这里是维护导航，不是要把现有游戏拆成新的框架。

1. 读游戏根目录 `AGENTS.md` 和 [双版同步规则](../EDITION-SYNC.md)，确认自己所在的是游戏目录。
2. 用 [任务路由表](TASK-ROUTER.md) 找到权威规则、展示入口与验证命令。
3. 只读对应专章；需要查反向调用时搜索 [全量文件索引](FILE-MAP.md) 或 `file-map.json`。
4. 按 [接单提示词](SMALL-MODEL-PROMPT.md) 完成局部修改，交付差异、验证和同步状态。
5. 发布走 [网页版运维手册](RUNBOOK.md)；小红书打包走其仓库的 `scripts/xhs/` 与合规说明。源码已推送、网站已部署、ZIP 已生成、平台已审核是四种不同状态。

## 日常维护只做三件事

- 公共修复在两版逐段同步，运行 `npm run check:editions -- --peer <另一游戏根目录>`；不要为了变绿批量放行哈希。
- 改了源码或测试文件，运行 `node scripts/maintenance/scan.mjs` 更新索引；`--check` 只读检查是否过期。专章中的数值是本次快照，公式和价格仍以当前源码为准。
- 行为变更补对应证据；纯文案/样式不写复刻实现的单测。UI 要看真实页面，存档要用历史样本，数值要看购买/结算结果。完整发布还须遵守 [发布要求](../RELEASE-CONTRACT.md)。

可直接交给小模型：明确的一处文案、一个组件的局部样式、已确定的新价格、一个纯 helper 的边界修复。

需要升级审查：收入计算、存档编码/迁移、建造事务、场景缓存、前台生命周期、跨版混合入口的大改。这里按修改风险分工，不按文件大小或模型名一刀切。

维护扫描需要完整源码、脚本及固定测试输入。稀疏副本缺少相对依赖时，生成和 `--check` 都应失败；先补齐已跟踪输入，不能改为忽略。主站整仓清单由 `inventory.mjs` 单独生成，不随一次游戏小修更新。
