# MC Clicker 2.0 · 网页版与小红书版同步规则

## 仓库边界

- 网页版：独立仓库 [`KevinYoung-Kw/mc-clicker`](https://github.com/KevinYoung-Kw/mc-clicker)，经营规则与公共 UI 的默认上游。
- 小红书版：独立的 [`mc-clicker-xhs`](https://github.com/KevinYoung-Kw/mc-clicker-xhs) 仓库，保留小红书适配标识。禁止搬入个人网站源码、部署配置、密钥或无关历史。
- 个人网站 [`my-profile`](https://github.com/KevinYoung-Kw/my-profile) 只托管线上静态产物 `public/projects/mc-clicker-2/`，不再作为网页版源码仓。
- MC Clicker 3.0、研究脚本和尚未确认的策划不自动同步。
- 两版可以独立发行；源代码同步完成不等于已经部署或通过平台审核。

## 每批改动的固定流程

1. 查看两边 Git 状态和 `docs/edition-sync-state.json` 的上次核查基线，保留其他线程未完成的改动。
2. 标明本批属于「公共经营／UI 修复」「平台适配」还是「性能回移」。公共修复在同一批次同步两版；不能只修改一个仓库后声称完成。
3. 逐文件核查。完全共用的文件可以同步；`main.js`、`world.js` 等混合平台差异的文件，按具体代码段移植，禁止整文件覆盖。
4. 把 `mc-clicker` 与 `mc-clicker-xhs` 放在同一父目录。`npm run check:editions` 默认找 `../mc-clicker-xhs`（网页）或 `../mc-clicker`（小红书）；路径不同时用 `--peer`。不要从 `my-profile` cherry-pick 游戏提交。分支、远端、冲突解决均以实际仓库为准。
5. 两边分别运行 `npm test` 和构建，验证本批真实操作及旧档继续使用。小红书额外运行离线打包与限制检查。性能改动完成同存档、同镜头的对照后才回移。
6. 运行 `npm run check:editions -- --peer <另一游戏根目录>`。共用文件不一致会失败；已登记的平台文件有任何变化也会失败，必须重新审核。
7. 对确实应保持不同的文件，在状态表记录原因及两边 SHA-256；不要用「整目录忽略」或批量接受差异来掩盖漏同步。状态表在两个仓库保持一致。
8. 更新各自版本号、锁文件、开发日志和玩家版本日志。记录测试证据、同步来源及部署状态；仅在本轮已有发布授权时推送／部署。

检查脚本只读文件，不后台监听、不自动覆盖代码。它核查 `src/`、`public/`、`tests/` 和入口／依赖／Vite 配置；构建脚本、部署流程、文档仍需人工对照本清单。同步历史记在下方；实际差异基线记在 JSON。

## 必须保留的平台差异

| 范围 | 网页版 | 小红书适配版 |
| --- | --- | --- |
| 分享与品牌 | 保留原站分享和主站入口 | 只导出纪念卡，使用相册桥接；无网址、二维码和站外引流 |
| 邮件 | 原站来信 | 游戏内来信；历史邮件 ID、领取进度与奖励计算不变 |
| 存档 | 原有下载、图片、Worker／WASM 解码路径 | 平台允许的图片／文本操作、本地主线程解码；历史格式仍可读 |
| 音乐资源 | 保留现有音轨 | 离线本地合成；不改收藏、岗位或演出收入 |
| 构建 | 原网站构建与资源路径 | 小工具离线普通脚本、ES2017 兼容、平台能力与包体约束 |
| 渲染预算 | 保持原画质与帧率策略 | 独立 WebView 预算与回退；不能反向覆盖网页设置 |

## 性能回移门槛

可以候选：计算结果相同的缓存／复用、同材质绘制合批、避免重复工作。必须检查真实调用方及失效条件。

不得顺带修改：模拟步长、生产／成交／运输速率、随机规则、暂停收益、存档字段、输入手势、粒子／模型细节、分辨率、帧率上限、阴影和截图质量。若需要这些取舍，单独提出，不能以「性能优化」名义混入。

至少对照主世界、下界、末地与直播室；记录绘制调用和几何数量、画面差异、配置恢复、动画与布局状态。绘制调用减少不等于 FPS 按相同比例增长，实体设备没有验证就不能承诺。
