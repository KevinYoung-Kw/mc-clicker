# V1.7 货运控制与状态修复

日期：2026-09-09。基于 V1.7.0-alpha.2 / 工作区 HEAD `ea3e69a`；本批已归入 **V1.7.0-alpha.3**，2026-09-09 已发布，发行提交 `b531673`。后续群聊核查与完整版本说明见[本批评估](ALPHA3-FEEDBACK-AUDIT.md)、[更新记录](../CHANGELOG.md)。

## 本任务边界

本任务负责复现缺陷、最小修复与回归验证。三个世界的差异玩法、30 / 60 / 90 分钟阶段目标和经济模拟由另一条任务负责。本批没有调整价格、产能、运输周期或自动采集规则。

## 已修复

| 问题 | 原因 | 修复后的行为 |
| --- | --- | --- |
| 恶魂 / 末影人暂停后找不到恢复入口 | 运输系统读取暂停标记，但详情控制只为可联网设施生成；两种搬运生物不属于电网设施 | 详情提供现有风格的播放 / 暂停图标，支持鼠标、键盘和触屏 |
| 旧档保存 `links=false` 后无法恢复非电力运输 | 原开关只修改 `disabled`，运输仍被另一标记拦住 | 仅在玩家明确点击恢复时清理非电力搬运者的旧标记；读档继续保留暂停意图，真正的电网断开状态不受影响 |
| 没货、满仓、暂停时仍显示“可发车” | 时间栏只检查班次时钟，没有检查真实运输条件 | 固定时间栏显示等待货物、目的仓已满、已暂停、等待传送门或等待供电；能发车时才显示可发车 |
| 基础末影龙运输被区域电网状态误报为缺电 | 状态展示先套用电力原因，而基础运输不需要用电 | 根据实际已购改造的耗电要求判断；需要供电的航标改造仍会在缺电时暂停 |

已经出发的货批继续遵循原运输逻辑：暂停保留货物和进度，恢复后继续；目的仓无空间时等待卸货。转运本身不重复发放绿宝石。
