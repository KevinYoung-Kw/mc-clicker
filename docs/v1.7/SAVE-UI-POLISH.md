# 图片存档 UI/UX 后续打磨

2026-09-10：先发布 alpha.15 已验证功能；以下为下一批界面改进，不阻挡本次上线。

| 优先级 | 当前冗余 | 下一步 | 验收 |
| --- | --- | --- | --- |
| P1 | 进度摘要和卡面重复展示多项数据 | 面板只突出保存时间、核心进度；卡面保留完整摘要 | 小屏首屏能看见图片与保存按钮 |
| P1 | 「完整进度在图片里」「已校验」「长按保存」等说明分散 | 合成图片下的一行状态，下载结果不重复长期占行 | 等待、成功、失败各只有一处主要反馈 |
| P1 | 存档码与 JSON 分在两处，多个备用入口抢注意力 | 合并「其他保存／读取方式」；保留容易找到的回退入口 | 图片为唯一首要操作，备用方式最多再点一次 |
| P2 | 更新按钮仅有回转图标，容易误认为撤销 | 精简图标与辅助名称；提示当前图片生成时间 | 玩家能辨认「更新图片」与「读取旧档」 |
| P2 | 小图可长按，但查看细节较费力 | 评估点图放大，关闭即回原面板；原图数据保持不变 | 放大、长按、返回不重制图片、不丢滚动位置 |

复用现有像素按钮、分隔线、主题变量与移动端排版，避免新增嵌套卡片。保留读取前摘要确认和本机备份，不能为省空间移除保护。外框和展示文案可改，数据区位置、尺寸、嵌入参数须冻结；更换图案必须重跑全主题压缩验证。

以上是在已交付功能上的界面整理；不增加购买环节、顶部入口或云端存储。
