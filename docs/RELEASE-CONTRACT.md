# 发布要求 · 更新可追溯，存档可延续

2026-09-10，用户明确列为每次更新必备项。此要求长期有效，独立于需求池中暂缓的体验专项。

## 更新日志

每个游戏发行批次，包括 Alpha 和热修复，发布前完成：

1. `package.json`、锁文件、发行版本保持一致。
2. `docs/CHANGELOG.md` 新增独立版本条目，写明新增、改动、修复及影响玩家的兼容事项。历史条目保留，区分本地与已发布。
3. `src/version-history.js` 同步玩家可见变化，仍在「世界信息 → 版本日志」按大版本归组，短小直白。纯技术补丁也说明解决了什么问题。
4. 发布后在 `DEPLOYMENT.md` 留下版本号、提交、备份、普通网址验证及存档验证证据。

## 存档兼容

| 验证场景 | 必须满足 |
| --- | --- |
| 旧浏览器存档升级 | 直接读入新版本，保留资源、购买、等级、布局、居民、岗位、货物、收藏、奖励领取与偏好；迁移不得重发收益 |
| 历史图片／存档码／JSON | 所有已发布且原本支持的格式继续可读；保留历史解码器、字典和样本 |
| 新增持久状态 | 正常保存和导出均覆盖；读档后行为一致，不能只让内存中的功能有效 |
| 连续使用 | 旧档读入 → 继续生产／操作 → 再保存 → 刷新／重新读入，进度与资产仍正确 |
| 跨设备／浏览器 | 导出 → 另一隔离浏览器导入 → 继续游玩；图片仍按已验证尺寸和压缩范围验收，不承诺任意裁切都可恢复 |
| 异常与取消 | 损坏、截断、不支持的未来格式明确拒绝；取消不覆盖，成功读档前保留当前进度备份 |

兼容目标是**旧版本的有效存档能在新版本继续使用**。新版本存档读入旧程序不作自动承诺；无法解释的新格式应明确拒绝，不能以空白世界代替。

## 每次发布的检查

- 运行 `npm test`，必须包含既有发行元数据、历史存档、图片与文本编解码、恢复及生产回归。不得删除失败样本来通过验收。
- 对本批新增或变更的持久状态补充针对性回归。沿用固定历史样本，不用当前编码器重新生成全部历史样本来替代旧数据。
- 在正式构建中，以隔离的前期／中期／后期存档验证读取、继续运行、再保存与重载；至少覆盖桌面和移动端浏览器。另验证跨浏览器图片导入、取消、坏图和备份恢复。
- 发布后用普通公开链接复核版本日志、存档入口及至少一条完整存读流程，记录证据。浏览器模拟不写成实体手机验收。
- 任一必要检查失败时修复后再发布；如上线后发现存档回归，停止继续发布并优先修复，保留原存档与恢复副本。

现有自动化入口：`tests/release.test.js`、`tests/save-*.test.js`、`tests/special-storage.test.js`。它们已覆盖版本日志条目、历史模拟样本、固定字典、图片纠错、旧格式、损坏拒绝及新增设施状态；自动化不能代替真实入口的完整存读检查。

本文件定义后续发布要求，不代表历史所有版本、所有实体设备已完成上述完整检查。已有证据以各版本的部署记录为准。
